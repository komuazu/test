# 稼動日報 印刷実績ビューア（26年）

`★新・26年稼動` フォルダの稼動日報 `.xls` を読み込み、
**26年すべての月 × 営業部別（本社・東京・池袋）** をブラウザで見られるようにするアプリです。

抽出・統合のルールは、これまでの「月次の営業部別 印刷実績集計」と**まったく同じ**です。

> **元のExcelファイルは絶対に変更しません。**
> 読み込みは必ず一時フォルダへコピーしてから行い、稼動日報フォルダには何も書き込みません。
> 画面で入力した内容は、このアプリのフォルダ内の `memo.json` に保存されます。

---

## 使い方

### 1. 起動する

このフォルダごと社内PCにコピーして、**`起動.bat` をダブルクリック**するだけです。

* 黒い画面が開いて稼動日報を読み込み、ブラウザが自動で立ち上がります
* 閉じるときは、黒い画面で **Ctrl + C** を押してください
* 初回だけ、必要なライブラリ（xlrd）の導入に少し時間がかかります

Python が入っていない場合は
[python.org](https://www.python.org/downloads/windows/) からインストールし、
インストール時に **「Add python.exe to PATH」にチェック**を入れてください。

### 2. フォルダの場所を設定する

初期設定は次のパスになっています。違っていれば、画面右上の **「設定」** から直してください。

```
U:\製造本部\第2工場\【第二工場】\☆第二工場日報・稼動報告\☆第二工場日報・稼動報告\★新・26年稼動
```

「保存して読み直す」を押すと、その場で読み直します。設定は `config.json` に残ります。

### 3. 日報が更新されたら

画面右上の **「データ更新」** を押すと、フォルダを読み直して最新の内容になります。
（入力済みの記入欄はそのまま残ります）

## 画面

| タブ | 内容 |
|---|---|
| **年間サマリー** | 年間の通し数・件数、営業部別の構成比、月別の積み上げ棒グラフ、月×営業部のマトリクス表 |
| **月別明細** | 月と営業部を選んで明細を表示。集計Excelと同じ10列・同じ並び順 |
| **得意先別** | 得意先ごとの年間ランキングと月別内訳。`㈱` と `（株）` の表記ゆれは同一得意先として集計 |
| **元ファイル** | 読み込んだ稼動日報の一覧と、統合前後で通し数が変わっていないことの検証結果 |

* マトリクス表の数字をクリックすると、その月・その営業部の明細に飛びます
* 各画面から **CSV出力**（Excelでそのまま開けます）・**印刷**ができます

## 集計ルール（従来の集計と同じ）

**営業部の振り分け**（営業担当ｺｰﾄﾞ基準。これ以外のコードは対象外）

| 営業部 | コード |
|---|---|
| 本社営業部 | 1110, 1120 |
| 東京営業部 | 2100, 2140 |
| 池袋営業部 | 3810, 3820 |

**抽出対象**

* シート名が `26年1月` 形式のものだけ（`26年1月30` のような日付付き補助シートは対象外）
* 日付セルにシリアル値が入っている明細行のみ
  （有効時間・準備合計・色合わせ・印刷時間・その他・受注件数 の日次集計ブロックは除外）
* 列の位置は月によって違うため、見出しの文字で列を特定します
* 「通し枚数」「表版数」「裏版数」は本刷ブロック（最初に現れた方）を採用します

**管理番号ごとの統合**

* 枝番は同一管理番号として統合（`8632175-1` と `8632175-1-2` は1件）
* 通し数 = グループ内の合計（表刷り＋裏刷り）
* 色数 = `表/裏`。表版数・裏版数それぞれの**最大値**（同じ版で複数回通した分を重複させない）
* 印刷日 = グループ内の**初日**。複数日にまたがる行は日付セルが黄色
* 品名 = 初日・管理番号・品名の順で最小の行のもの
* ｸﾗｲｱﾝﾄ名 = グループ内の非空値の最頻値 → 同数なら最も長いもの

**並び順**

1. 営業担当ｺｰﾄﾞ 降順
2. ｸﾗｲｱﾝﾄ名 降順（`㈱` と `（株）`、全角半角スペースの違いは同一視。空欄は各コードの末尾）
3. 印刷日 降順

**記入欄（山吹色の3列）**

`今年の動向` / `無しの場合の代替対策` / `対策通し数` は手入力欄です。
入力すると合計・差引（通し数 − 対策通し数）・充足率が自動で計算されます。
内容は `memo.json` に保存され、**元のExcelには書き戻されません**。

## ファイル構成

```
kadou-web/
├── 起動.bat            ← これをダブルクリック
├── server.py            ローカルサーバー（記入欄の保存・データ更新）
├── build.py             稼動日報フォルダ → web/data.json
├── kadou_core.py        抽出・統合ルール（元ファイルは読み取りのみ）
├── web/
│   ├── index.html       画面
│   ├── app.js           表示・集計・CSV出力
│   ├── style.css        見た目
│   └── data.json        生成データ（起動のたびに作り直し）
├── config.json          フォルダの場所・対象年（初回起動時に作成）
├── memo.json            記入欄の内容（入力すると作成）
└── tests/
    ├── make_fixture.py  検証用のダミー稼動日報を作る
    └── ui_test.py       画面の自動テスト
```

---

## コマンドで使う場合

```bash
# データだけ作る
python build.py --src "U:\...\★新・26年稼動" --year 2026

# サーバーを起動（ポート変更・ブラウザを開かない、なども可）
python server.py --src "U:\...\★新・26年稼動" --year 2026 --port 8765
python server.py --no-build      # 読み直さず前回のデータで起動
```

`--year` を変えれば 27年以降や、25年の振り返りにもそのまま使えます。

## 動作確認

ダミーの稼動日報で、抽出・統合・画面表示・記入欄の保存までを自動テストしています。

```bash
python tests/make_fixture.py /tmp/sample        # ダミーデータ作成
python build.py --src /tmp/sample --year 2026   # 抽出
python server.py --src /tmp/sample --no-browser &
python tests/ui_test.py                         # 画面テスト（要 playwright）
```
